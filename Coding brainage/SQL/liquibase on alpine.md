Общая идея:
- в src проекта заводится файл changelog.sql в котором сложены все миграции, размеченные идентификаторами миграций
- отдельной командой миграции из этого файла накатываются на указанную БД
- после накатывания миграций на базу можно повесить тег версии, который закрепит последние накаченные не тегнутые миграции этой версией
- при необходимости выполнить роллбек можно одной командой запустить down-миграции вплоть до последней, на которой висит тег указанной версии
- совместимость с разными БД реализована через драйвера, которые надо качать отдельно (.jar файл)

Проблемы эксплуатации:
- драйвер для sqlite не включен в дистрибутив liquibase начиная с версии 5.0.0, пришлось скачать его руками
- чтобы работали все команды, нужно явно указывать путь до этой утилиты: `liquibase <command> --classpath=/path/to/sqlite-sem.ver.slug.jar`

МБ можно запихать путь до `.jar` в настройки bash, чтобы ссылаться на него более лаконичным способом.

## Нулевая миграция

инициализируем БД в файле `migrations.sql`
```sql
--liquibase formatted sql

-- changeset create-table:1
create table person(id integer primary key, name text);
-- rollback drop table person;
```
- все комменты здесь важны для правильной работы `liquibase`

запустить миграцию
```bash
liquibase update --changelog-file=migrations.sql --url=jdbc:sqlite:./db.sqlite3 --classpath=/path/to/sqlite-sem.ver.slug.jar
```
- migrations.sql - это файл из предыдущего (первого) листинга. Канонически он называется `changelog.sql` (?)

Далее посмотрим на состояние БД:
```sql
.tables

-- таблица с людьми соответствует запрошенной схеме:

.mode box -- красивое отображение
select * from person;
┌────┬────────────────┐
│ id │      name      │
├────┼────────────────┤

```

## Проект затребовал обновления модели и значений в БД

В `migrations.sql` добавляется новая миграция

```sql
--liquibase formatted sql

-- changeset create-table:1
create table person(id integer primary key, name text);
-- rollback drop table person;

-- changeset create-table:2
update person set name = concat(name, '__migrated_suffix');
-- rollback update person set name = replace(name, '__migrated_suffix', '');
```

накатываем миграцию и тегируем её сразу:
```bash
liquibase update --changelog-file=migrations.sql --url=jdbc:sqlite:./db.sqlite3 --classpath=/path/to/sqlite-sem.ver.slug.jar
liquibase tag '0.0.2' --url=jdbc:sqlite:./db.sqlite3 --classpath=/path/to/sqlite-sem.ver.slug.jar
```

## Версия содержала баг в ПО, пришлось откатиться на предыдущую стабильную версию
просим liquibase запустить все down-миграции вплоть до версии, которая нас интересует:
```bash
liquibase rollback '0.0.1' --changelog-file=migrations.sql --url=jdbc:sqlite:./db.sqlite3 --classpath=/path/to/sqlite-sem.ver.slug.jar
```
