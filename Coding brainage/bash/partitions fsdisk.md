
Утилита для настройки разбиения памяти на устройстве: fsdisk.

Работа с ней состоит из декларативной разметки партишнов и применения этой разметки.

У партишнов бывают разные типы
- `b` - бутлоадер
- `83` под какую-то конкретную структуру (файловую систему)
- `5`, который объединяет несколько под-партишнов, ограничивает их в размере
- `da`, область памяти, в которую можно просто тупа писать или читать байты

пример разбиения памяти на секции:
```
# partition.sfdisk

label: dos
label-id: 0xa7f044bf
device: img
unit: sectors
sector-size: 512

img1 : start=        2048, size=     1048576, type=b
img2 : start=     1050624, size=     9448128, type=5
img3 : start=     1052672, size=     4194304, type=da
img4 : start=     5249024, size=     4194304, type=83
```

в описанном разбиении выстраивается иерархия:
```
im1 - boot partition

img2 - контейнер для двух под-разбиений
	img3 - байтовые данные (спойлер, там может быть зашифрованная подписанная ключом файловая система, которую надо распаковывать при загрузке устройства)
	 например може использоваться для сорсов, которые поставлены в систему разработчиком, которые должно быть нельзя подменить, бут сверяет достоверность
	img4 - партишн для файловой системы - файлы здесь создаются во время штатной работы устройства, персистятся между рабочими сессиями
```

тонкости:
зачастую размеры кратны 512 байтам - это какой-то sector-size. То ли легаси, то ли для ускорения адресации.

EBR:
можно заметить, что start + size партишона N - не равно start партишона N+1.
Это связано с тем, что перед началом партишна обычно нужно оставить какое-то количество байт для хедеров.
Суть этих хедеров в том, чтобы настроить что-то типа двусвязного списка из партишнов, чтобы ОС(?) или бутлоадер(?) или утилиты для разбиения памяти умели по ним адресоваться

расписать конкретные числа по коду сверху

### Изменение размера partition

предположим теперь, что img2 заканчивается не в конце памяти устройства, а в середине. То есть, партишн можно увеличить при необходимости.

Делается это так:

```bash
sfdisk -N 2 --no-reread /dev/mmcblk0
```

- партишны лежат все по пути `/dev/mmcblk0`. Это типа их точка входа.
- -N 2 - указывает `sfdisk`-у, что мы хотим сделать что-то с img2
- `--no-reread` - чета

Так sfdisk понимает, с каким блоком в разбиениях будет идти работа.

Есть какой-то стремный язык с командами для управления партишнами:
```bash
echo ", +" | sfdisk -N 2 --no-reread /dev/mmcblk0
```
- `", + "` - означает занять всё доступное пространство.

Так увеличивается только img2 - контейнер. Далее можно увеличить партишн, в котором лежат данные, который внутри img2:
```bash
echo ", +" | sfdisk -N 4 --no-reread /dev/mmcblk0
```

#### указание конкретного размера partition

Пример обратного преобразования, в котором эти же два partition-а сжимаются обратно до конкретного размера
```bash
echo ", 1048576" | sfdisk -N 4 --no-reread /dev/mmcblk0
echo ", 9448128" | sfdisk -N 2 --no-reread /dev/mmcblk0
```
